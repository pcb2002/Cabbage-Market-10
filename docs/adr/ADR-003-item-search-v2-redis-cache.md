# ADR-003 상품 검색 v2 Redis 캐시

## Status

Accepted

## Context

상품 검색 v2는 공개 검색, 정렬, 필터, 좋아요 기반 조건을 포함하며 조회 빈도가 높다.
애플리케이션 인스턴스가 여러 대로 늘어나면 프로세스 메모리 기반 local cache는 인스턴스마다 값이 갈라져
캐시 적중률과 일관성이 떨어진다.
검색 v2는 상품 생성, 수정, 상태 변경, 삭제, 좋아요 토글, 입찰 같은 쓰기 작업 이후 결과 반영이 중요하므로
모든 인스턴스가 같은 캐시를 공유해야 한다.

## Decision

상품 검색 v2 캐시는 Redis remote cache를 기본 저장소로 사용한다.

- 캐시 이름은 `itemSearchV2`를 사용한다.
- 캐시 TTL과 key prefix는 `app.cache.item-search-v2.*` 설정으로 관리한다.
- 검색 v2 결과는 비로그인 공개 검색 요청만 캐시한다.
- 로그인 사용자 전용 검색(`likedOnly`, `likedByMe`)은 회원별 결과 차이와 오염 위험 때문에 캐시하지 않는다.
- 상품 생성, 게시, 수정, 상태 변경, 삭제, 좋아요 토글, 입찰 성공 후 검색 캐시는 트랜잭션 커밋 이후 무효화한다.
- Redis 장애나 연결 실패는 검색 캐시 계층 장애로 간주하며, 운영 환경은 Redis 가용성을 제공해야 한다.

## Consequences

- 다중 인스턴스 환경에서도 같은 검색 조건에 대해 동일한 캐시를 공유할 수 있다.
- 검색 결과 반영 일관성은 좋아지지만, 검색 v2는 Redis 가용성과 네트워크 지연의 영향을 받는다.
- 캐시 무효화는 반드시 커밋 이후에 실행해야 stale 데이터 재적재를 줄일 수 있다.
- 테스트는 Redis 캐시 저장/재사용과 쓰기 작업 이후 캐시 무효화 경로를 함께 검증해야 한다.
